# [Hero Duty]

**Hero Duty** — это мобильная аркадная головоломка-файтинг с физическим уклоном. Разработка проекта была сфокусирована на создании уникальных геймплейных механик через процедурную физику и алгоритмы.

> **Примечание для .NET бэкенд рекрутеров:** Хотя GitHub может ошибочно определять язык ShaderLab как доминирующий, этот репозиторий содержит значительную часть C# кода. Этот проект был разработан мной, Дмитрием Прокофьевым, как демонстрация навыков написания сложной физической и геометрической логики на C#, а также реализации асинхронных систем. Шейдеры (ShaderLab) использовались лишь для графической оптимизации проекта и являются второстепенными по отношению к архитектуре кода.

## Технологический стек
* **Язык программирования:** C# 
* **Платформа:** Unity 

## Архитектурные решения и инженерный фокус

В данном проекте я уделил особое внимание реализации сложных систем через C#, минимизируя использование встроенных анимаций в пользу процедурных алгоритмов:

### 1. Процедурная физика и сложные геометрические алгоритмы
Я разработал сложную систему процедурного падения объектов (класс `FallingObject.cs`), которая не использует анимации, а полностью рассчитывается в C#:
* **Сложная математика:** Реализован алгоритм вычисления точного направления падения относительно игрока (фильтрация произвольного вектора в 4 cardinal directions: Up, Down, Left, Right).
* **Динамические вычисления:** Программно вычисляются: ось вращения (через `Vector3.Cross`) и динамическая точка вращения (пивот) на основе коллизий объекта.
* **Процедурная асинхронная анимация:** Внедрена корутина для неблокирующего procedural-вращения объекта вокруг динамического пивота over time.

### 2. Raycasting и алгоритмы предсказательной остановки
В классе `Player.cs` я реализовал систему продвинутого управления движением через Rigidbody и физические запросы:
* **Уникальный алгоритм:** Вместо использования стандартных коллизий для остановки, я внедрил `Raycast` для **предварительного** расчета точного расстояния до препятствия (`stopDistance`).
* **Оптимизация:** Это позволяет программно остановить игрока точно перед стеной в `FixedUpdate`, предотвращая физические ошибки ("туннелирование").

### 3. Комплексная Булева Логика и Rules Engine
Для обработки различных ситуаций взаимодействия с миром (класс `reaction.cs`) я разработал сложную систему, основанную на тегах и внешних состояниях:
* **Техническая реализация:** Код обрабатывает множество условий (N-ое количество тегов, состояния боссов и т.д.), фактически реализуя упрощенный **Rules Engine** на C#.
* **Маркер навыка:** Это решение показывает умение проектировать сложные системы фильтрации данных или движки правил, применимые в бэкенд-разработке.

### 4. Асинхронное управление состоянием систем
Реализация сложных временных логик (кулдауны, последовательности действий) была выполнена с использованием асинхронных **корутин**:
* Реализована система последовательных атак, временного отключения камеры и пересчета логики после телепортации (`OnTeleport`).

## Как изучить код проекта
Самые интересные с точки зрения архитектуры на C# файлы находятся в папке: `/Src/Scripts/Character` и `/Src/Scripts/Objects/ProceduralPhysics`. Рекомендую обратить внимание на:
* `FallingObject.cs` — процедурная физика, рекурсивные и геометрические алгоритмы.
* `Player.cs` — raycasting, предсказательная логика движения и асинхронность.
* `reaction.cs` — сложная условная логика (Rules Engine).

## Отказ от ответственности
Некоторые классы в данном проекте (например, `Player.cs`) могут быть перегружены ответственностью из-за жестких временных ограничений при разработке. Я полностью осознаю важность принципа единственной ответственности (SRP) и в коммерческой бэкенд-разработке применяю практики рефакторинга для декомпозиции God-объектов на более мелкие, специализированные сервисы.
